## Содержание лабораторных работ

### Лабораторная работа №1. Примитивный поиск дефектов в ПО. Тестирование формы входа

**Цель:** Научиться выполнять примитивный поиск дефектов, освоить базовые принципы тестирования формы входа.

**Задания:**
- Написать программу определения типа треугольника по трём сторонам.
- Протестировать программу другого студента.
- Протестировать форму входа веб- или мобильного приложения.
- Составить чек-лист для тестирования формы входа.

**Ключевые проверки формы входа:**
- Доступность формы на сайте.
- Наличие полей логина, пароля, кнопки входа и ссылки «забыли пароль?».
- Положение курсора после загрузки формы.
- Валидация данных (пустые поля, неверные данные).
- Сообщения об ошибках.
- Чувствительность к регистру (для пароля).
- Ограничение на число неудачных попыток.
- Работа кнопок браузера «вперед» и «назад».

### Лабораторная работа №2. Построение баг-репорта

**Цель:** Научиться оформлять баг-репорты, понимать градации серьезности и приоритета дефектов.

**Задания:**
- Изучить структуру баг-репорта.
- Изучить градации серьезности (S1-S5) и приоритета (P1-P3).
- Выполнить поиск багов на сайтах.
- Оформить не менее 3 баг-репортов.

**Структура баг-репорта:**

| Раздел | Описание |
|--------|----------|
| Короткое описание | Краткое описание проблемы (принцип «Где? Что? Когда?») |
| Проект | Название тестируемого проекта |
| Компонент | Название части или функции продукта |
| Номер версии | Версия, на которой найдена ошибка |
| Серьезность | S1-S5 (Blocker → Trivial) |
| Приоритет | P1-P3 (High → Low) |
| Статус | Open, In Progress, Fixed, Closed |
| Шаги к воспроизведению | Подробные шаги для воспроизведения |
| Фактический результат | Что происходит на самом деле |
| Ожидаемый результат | Что должно происходить |
| Прикрепленный файл | Скриншоты, логи и т.д. |

**Градация серьезности:**
- **S1 Blocker** — работа с системой невозможна.
- **S2 Critical** — ключевая бизнес-логика нарушена.
- **S3 Major** — часть бизнес-логики работает некорректно.
- **S4 Minor** — проблема пользовательского интерфейса.
- **S5 Trivial** — не влияет на качество продукта.

### Лабораторная работа №3. Чек-лист. Классы эквивалентности. Граничные значения

**Цель:** Научиться составлять чек-листы, строить классы эквивалентности, применять технику тестирования граничных значений.

**Задания:**
- Составить чек-лист для веб-формы оформления заказа.
- Определить классы эквивалентности для калькулятора доставки.
- Применить технику граничных значений.
- Составить сводную таблицу тестовых сценариев.

**Типы классов эквивалентности:**
1. **Непрерывные** — диапазон значений (например, 0-5 кг).
2. **Дискретные** — отдельные значения (например, 1-5 домов).
3. **С одним возможным значением** (например, «человек»).
4. **С несколькими возможными значениями** (например, типы жилья).

**Граничные значения** — значения на границах классов эквивалентности (нижняя, верхняя, внутри, за пределами).

### Лабораторная работа №4. Таблицы решений. Попарное тестирование

**Цель:** Научиться строить таблицы решений, применять технику попарного тестирования.

**Задания:**
- Построить таблицу решений для системы одобрения заявки на кредитную карту.
- Выполнить оптимизацию (свертку) таблицы.
- Составить тест-кейсы на основе оптимизированной таблицы.
- Применить попарное тестирование для настройки уведомлений.

**Таблица решений** — формализация бизнес-правил, где каждое правило становится тест-кейсом.

**Попарное тестирование** — техника, при которой тестируются все возможные пары значений параметров (3×3×3×3 = 81 → ~9-12 тестов).

### Лабораторная работа №5. Комбинаторное тестирование. Диаграмма состояний

**Цель:** Научиться применять комбинаторное тестирование с ограничениями, строить диаграммы состояний и переходов.

**Задания:**
- Применить комбинаторное тестирование для конфигуратора ноутбука.
- Построить диаграмму переходов состояний для умной кофемашины.
- Создать таблицу переходов.
- Выделить критичные тестовые сценарии.

**Комбинаторное тестирование** — учитывает бизнес-ограничения, исключающие некоторые комбинации.

**Диаграмма состояний** — модель поведения системы, показывающая состояния и переходы между ними.

### Лабораторная работа №6. Сценарное и исследовательское тестирование

**Цель:** Научиться составлять сценарии тестирования для веб-приложений.

**Задания:**
- Выбрать 3 задачи из списка (54 варианта).
- Описать подробные сценарии тестирования.

**Сценарное тестирование** — разделение задачи на этапы и последовательное выполнение.

**Пример сценария:**
1. Перейдите на стартовую страницу.
2. Нажмите на кнопку «Новый».
3. В поле «Кому» напишите адрес.
4. ... и т.д.

### Лабораторная работа №7. Отчеты о тестировании

**Цель:** Научиться составлять формальные отчеты о тестировании.

**Задания:**
- Изучить структуру отчета о тестировании.
- Проанализировать предоставленные данные.
- Составить полный отчет о тестировании модуля «Онлайн-запись к врачу».
- Сформулировать выводы и рекомендации.

**Структура отчета:**
1. Идентификация документа (Header).
2. Резюме для руководства (Executive Summary).
3. Объем тестирования (Scope of Testing).
4. Методология тестирования (Testing Approach).
5. Результаты и метрики (Results and Metrics).
6. Оценка качества (Quality Assessment).
7. Выводы и рекомендации (Conclusions and Recommendations).
8. Приложения (Appendices).

**Ключевые метрики:**
- Процент успешных тестов = Passed / Total × 100%.
- Плотность дефектов = Defects / Test Cases.

### Лабораторная работа №9. Тестирование строки поиска

**Цель:** Научиться проводить всестороннее тестирование строки поиска.

**Задания:**
- Составить структурированный чек-лист для тестирования поиска.
- Включить не менее 5 «хитрых» сценариев.
- Оформить отчет.

**Основные проверки поиска:**
- Поиск по всем полям из ТЗ.
- Поиск НЕ по полям не из ТЗ.
- Релевантность выдачи.
- Контекст поиска.
- Регистронезависимость.
- Поиск по включению/совпадению.
- Два слова из одного/разных полей.
- Ошибки в вводе (опечатки).
- Неправильная раскладка клавиатуры.
- Спецсимволы и эмоджи.
- Пробелы (открывающие/закрывающие).
- Пустое поле и только пробелы.
- Нижняя и верхняя границы.
- Технологическая граница (большой объем данных).

### Лабораторная работа №11. Написание автотестов с Selenium WebDriver

**Цель:** Освоить написание автоматизированных UI-тестов с использованием Selenium WebDriver и паттерна Page Object Model.

**Задания:**
- Настроить окружение (Maven/Gradle, Selenium, JUnit).
- Реализовать Page Object Model для страниц тестового приложения.
- Написать позитивные и негативные сценарии тестирования формы входа.
- Оформить отчет.

**Selenium WebDriver** — инструмент для автоматизации действий в веб-браузерах.

**Page Object Model (POM)** — паттерн, при котором каждая страница представляется отдельным классом.

**Матрица сценариев для формы входа:**

| Сценарий | Логин | Пароль | Ожидаемый результат |
|----------|-------|--------|---------------------|
| Позитивный | valid@mail.ru | ValidPass123 | Переход на главную страницу |
| Негативный | valid@mail.ru | wrong | Сообщение об ошибке |
| Негативный | wrong@mail.ru | ValidPass123 | Сообщение об ошибке |
| Негативный | (пусто) | (пусто) | Сообщение об ошибке |

### Лабораторная работа №12. Модульное тестирование с JUnit и Mockito

**Цель:** Освоить модульное тестирование в Java с использованием JUnit 5 и Mockito.

**Задания:**
- Написать модульные тесты для сервисного слоя приложения.
- Использовать Mockito для создания mock-объектов.
- Проверить обработку исключений и граничные условия.
- Реализовать параметризованные тесты для валидации данных.

**JUnit 5** — фреймворк для модульного тестирования.

**Mockito** — библиотека для создания mock-объектов.

**Основные аннотации JUnit 5:**
- `@Test` — тестовый метод.
- `@BeforeEach` / `@AfterEach` — подготовка/очистка.
- `@ParameterizedTest` — параметризованный тест.

### Лабораторная работа №13. Генерация автотестов с ИИ-инструментами

**Цель:** Освоить применение ИИ-инструментов для генерации автотестов, научиться оценивать качество сгенерированного кода.

**Задания:**
- Установить и настроить ИИ-плагин (JAIPilot / GitHub Copilot).
- Сгенерировать тесты для Java-класса.
- Проанализировать и доработать сгенерированный код.
- Сравнить ручной и автоматизированный подходы.

**ИИ-инструменты:**
- **JAIPilot** — AI-плагин для IntelliJ IDEA.
- **GitHub Copilot** — генерация тестов через чат-интерфейс.

**Эффективный промпт** должен содержать:
- Цель (Goal).
- Контекст (Context).
- Правила (Rules/Style).
- Формат вывода (Output Format).

**Ограничения ИИ:**
- Галлюцинации (несуществующие методы).
- Отсутствие контекста.
- Обязательная проверка кода.
