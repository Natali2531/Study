## 2. Теоретический конспект

### 2.1. Парадигмы программирования

**Процедурное программирование** — парадигма, в которой программа представляется как последовательность инструкций, выполняемых над данными. Данные и функции раздельны.

**Объектно-ориентированное программирование (ООП)** — парадигма, в которой программа представляется как совокупность взаимодействующих объектов. Каждый объект объединяет данные (состояние) и функции (поведение).

**Преимущества ООП:**
- моделирование предметной области через объекты;
- повторное использование кода через наследование и композицию;
- управление сложностью через инкапсуляцию;
- гибкость через полиморфизм.

### 2.2. Классы и объекты

**Класс** — чертёж (шаблон) для создания объектов. Определяет структуру (поля) и поведение (методы).

**Объект** — экземпляр класса, имеющий конкретное состояние.

```java
// Объявление класса
public class Book {
    // Поля (состояние)
    private long id;
    private String title;
    private String author;
    private int year;

    // Методы (поведение)
    public String getDescription() {
        return "\"" + title + "\" — " + author + " (" + year + ")";
    }
}
```

### 2.3. Модификаторы доступа

| Модификатор | Класс | Пакет | Подкласс | Все |
|-------------|:-----:|:-----:|:--------:|:---:|
| `private`   | ✓     | ✗     | ✗        | ✗   |
| (по умолчанию) | ✓  | ✓     | ✗        | ✗   |
| `protected` | ✓     | ✓     | ✓        | ✗   |
| `public`    | ✓     | ✓     | ✓        | ✓   |

**Правило:** поля класса объявляются `private`, методы доступа — `public`.

### 2.4. Инкапсуляция

**Инкапсуляция** — механизм объединения данных и методов в классе и сокрытия внутренней реализации.

**Зачем нужна инкапсуляция:**
- защита состояния от некорректных значений;
- возможность изменения внутренней реализации без влияния на внешний код;
- централизация валидации.

```java
public class Book {
    private String title;

    // Getter
    public String getTitle() {
        return title;
    }

    // Setter с валидацией
    public void setTitle(String title) {
        if (title == null || title.isBlank()) {
            throw new IllegalArgumentException("Название не может быть пустым");
        }
        this.title = title;
    }
}
```

### 2.5. Ключевое слово `this`

Ключевое слово `this` ссылается на текущий объект:

```java
public void setYear(int year) {
    if (year < 0 || year > java.time.Year.now().getValue()) {
        throw new IllegalArgumentException("Некорректный год: " + year);
    }
    this.year = year;  // this.year — поле класса, year — параметр
}
```

### 2.6. Классы-обёртки и автоупаковка

Для каждого примитивного типа существует класс-обёртка:

| Примитив | Обёртка |
|----------|---------|
| `int`    | `Integer` |
| `double` | `Double` |
| `boolean`| `Boolean` |
| `long`   | `Long` |

**Автоупаковка** — автоматическое преобразование примитива в обёртку:
```java
Integer n = 42;  // автоупаковка: Integer.valueOf(42)
int m = n;       // автораспаковка: n.intValue()
```

1. **Создать проект** в IntelliJ IDEA:

   - `id` (long) — уникальный идентификатор;
   - `title` (String) — название;
   - `author` (String) — автор;

5. **Коммитьте код в Git** после каждого значимого изменения с осмысленным сообщением.
