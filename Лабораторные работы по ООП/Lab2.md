## 2. Теоретические сведения

### 2.1. Недостатки классов с публичными полями

В лабораторной работе №1 были рассмотрены классы, поля которых имели модификатор доступа по умолчанию (package-private) и были доступны для непосредственного изменения извне:

```java
public class Student {
    String name;
    int age;
    String group;
}
```

Подобный подход имеет существенные недостатки:

1. **Отсутствие контроля над состоянием.** Внешний код может присвоить полю недопустимое значение (например, отрицательный возраст).
2. **Нарушение инвариантов класса.** Класс не способен гарантировать корректность своего состояния.
3. **Сложность модификации реализации.** При изменении внутренней структуры класса потребуется модифицировать весь внешний код, работающий с его полями.
4. **Невозможность выполнения побочных действий.** При изменении поля нельзя выполнить дополнительные действия (логирование, уведомление, пересчёт связанных полей).

Указанные недостатки устраняются посредством применения принципа инкапсуляции.

### 2.2. Принцип инкапсуляции

**Инкапсуляция** — принцип объектно-ориентированного программирования, заключающийся в объединении данных и методов, обрабатывающих эти данные, в едином классе и сокрытии внутренней реализации от внешних потребителей.

Инкапсуляция преследует три основные цели:

1. **Защита состояния объекта.** Класс самостоятельно контролирует допустимые значения своих полей.
2. **Сокрытие реализации.** Внутренняя структура класса может изменяться без влияния на внешний код.
3. **Снижение связности.** Внешний код взаимодействует с классом посредством чётко определённого интерфейса (набора публичных методов).

### 2.3. Модификаторы доступа

Язык Java предоставляет четыре уровня доступа, определяющих видимость членов класса (полей, методов, конструкторов):

| Модификатор | Класс | Пакет | Подкласс (другой пакет) | Все прочие |
|-------------|:-----:|:-----:|:-----------------------:|:----------:|
| `private`   | ✓     | ✗     | ✗                       | ✗          |
| (не указан) | ✓     | ✓     | ✗                       | ✗          |
| `protected` | ✓     | ✓     | ✓                       | ✗          |
| `public`    | ✓     | ✓     | ✓                       | ✓          |

В рамках настоящей работы применяется следующее правило:

- все поля класса объявляются с модификатором `private`;
- методы, предназначенные для внешнего взаимодействия, объявляются с модификатором `public`;
- вспомогательные методы, используемые только внутри класса, объявляются с модификатором `private`.

Модификаторы `protected` и package-private будут подробно рассмотрены в лабораторной работе №3 при изучении наследования.

### 2.4. Методы-аксессоры и методы-мутаторы

Для обеспечения контролируемого доступа к приватным полям применяются специальные методы:

**Метод-аксессор (геттер)** — метод, предназначенный для чтения значения поля. Именование: `get` + имя поля с прописной буквы (для полей типа `boolean` допускается префикс `is`).

**Метод-мутатор (сеттер)** — метод, предназначенный для изменения значения поля. Именование: `set` + имя поля с прописной буквы.

```java
public class Student {
    private String name;
    private int age;

    // Геттеры
    public String getName() {
        return name;
    }

    public int getAge() {
        return age;
    }

    // Сеттеры
    public void setName(String name) {
        this.name = name;
    }

    public void setAge(int age) {
        this.age = age;
    }
}
```

### 2.5. Валидация состояния

**Валидация** — проверка корректности значений, передаваемых в методы-мутаторы и конструкторы. Валидация обеспечивает соблюдение **инвариантов класса** — условий, которые должны выполняться на протяжении всего жизненного цикла объекта.

При обнаружении некорректных данных метод должен прервать выполнение и сообщить о проблеме. В языке Java для этой цели применяется механизм исключений:

```java
public void setAge(int age) {
    if (age < 16 || age > 100) {
        throw new IllegalArgumentException(
            "Возраст должен находиться в диапазоне от 16 до 100 лет. " +
            "Получено значение: " + age);
    }
    this.age = age;
}
```

Класс `IllegalArgumentException` — стандартное исключение библиотеки Java, применяемое для сигнализации о некорректных аргументах методов.

### 2.6. Конструкторы

**Конструктор** — специальный метод, вызываемый при создании объекта оператором `new` и предназначенный для инициализации его состояния.

Характерные признаки конструктора:
- имя конструктора совпадает с именем класса;
- конструктор не объявляет возвращаемого типа, включая `void`;
- конструктор не может быть вызван явно — он выполняется автоматически при создании объекта.

Если в классе не определён ни один конструктор, компилятор автоматически генерирует **конструктор по умолчанию** без параметров, инициализирующий поля значениями по умолчанию (`0`, `null`, `false`).

```java
public class Student {
    private String name;
    private int age;

    // Конструктор по умолчанию
    public Student() {
        this.name = "Не указано";
        this.age = 18;
    }

    // Параметризованный конструктор
    public Student(String name, int age) {
        setName(name);   // валидация через метод-мутатор
        setAge(age);     // валидация через метод-мутатор
    }
}
```

**Рекомендация.** В параметризованных конструкторах следует вызывать методы-мутаторы для инициализации полей, чтобы обеспечить выполнение валидации на этапе создания объекта.

### 2.7. Перегрузка конструкторов

В классе может быть определено несколько конструкторов с различными списками параметров. Это позволяет создавать объекты, предоставляя различный объём исходных данных:

```java
public class Student {
    private String name;
    private int age;
    private String group;
    private double averageGrade;

    public Student() {
        this("Не указано", 18, "Не указана", 0.0);
    }

    public Student(String name, int age) {
        this(name, age, "Не указана", 0.0);
    }

    public Student(String name, int age, String group) {
        this(name, age, group, 0.0);
    }

    public Student(String name, int age, String group, double averageGrade) {
        setName(name);
        setAge(age);
        setGroup(group);
        setAverageGrade(averageGrade);
    }
}
```

### 2.8. Ключевое слово `this`

Ключевое слово `this` представляет ссылку на текущий экземпляр класса и применяется в следующих случаях:

**1. Устранение неоднозначности** между полями класса и параметрами методов с совпадающими именами:

```java
public void setName(String name) {
    this.name = name;   // this.name — поле класса, name — параметр
}
```

**2. Вызов одного конструктора из другого** посредством конструкции `this(...)`. Вызов должен располагаться первой инструкцией в теле конструктора:

```java
public Student(String name, int age) {
    this(name, age, "Не указана", 0.0);   // вызов конструктора с 4 параметрами
}
```

**3. Передача текущего объекта** в качестве аргумента метода:

```java
public void registerInSystem(Registry registry) {
    registry.register(this);   // передача текущего объекта
}
```

### 2.9. Статические члены класса

**Статические поля и методы** принадлежат не конкретному объекту, а классу в целом. Они существуют в единственном экземпляре независимо от количества созданных объектов.

**Статическое поле** объявляется с модификатором `static` и применяется для хранения данных, общих для всех объектов класса (счётчики, константы, конфигурационные значения):

```java
public class Student {
    private static int studentCount = 0;   // счётчик созданных объектов
    private String name;

    public Student(String name) {
        this.name = name;
        studentCount++;   // увеличение счётчика при создании объекта
    }

    public static int getStudentCount() {
        return studentCount;
    }
}
```

**Статический метод** не имеет доступа к нестатическим полям и методам класса (поскольку вызывается без создания объекта):

```java
public static int getStudentCount() {
    return studentCount;   // обращение к статическому полю допустимо
    // return name;        // ОШИБКА: обращение к нестатическому полю
}
```

Вызов статических методов осуществляется через имя класса:

```java
int count = Student.getStudentCount();
```

### 2.10. Блоки инициализации

**Блок инициализации** — конструкция, выполняемая при создании объекта до вызова конструктора. Применяется для инициализации полей, требующих выполнения вычислений:

```java
public class Configuration {
    private Map<String, String> settings;

    // Блок инициализации
    {
        settings = new HashMap<>();
        settings.put("language", "ru");
        settings.put("theme", "light");
    }
}
```

**Статический блок инициализации** выполняется однократно при загрузке класса и применяется для инициализации статических полей:

```java
public class Constants {
    public static final List<String> DAYS_OF_WEEK;

    static {
        DAYS_OF_WEEK = new ArrayList<>();
        DAYS_OF_WEEK.add("Понедельник");
        DAYS_OF_WEEK.add("Вторник");
        // ...
    }
}
```

## 3. Примеры выполнения

### 3.1. Пример 1. Эволюция класса: от публичных полей к инкапсуляции

Рассмотрим последовательное улучшение класса `Student` с применением принципа инкапсуляции.

**Начальный вариант (лабораторная работа №1):**

```java
public class Student {
    String name;
    int age;
    String group;
    double averageGrade;
}
```

Недостатки: отсутствие контроля над состоянием, возможность присвоения недопустимых значений.

**Промежуточный вариант:** поля приватизированы, добавлены геттеры и сеттеры без валидации:

```java
public class Student {
    private String name;
    private int age;
    private String group;
    private double averageGrade;

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public int getAge() { return age; }
    public void setAge(int age) { this.age = age; }

    public String getGroup() { return group; }
    public void setGroup(String group) { this.group = group; }

    public double getAverageGrade() { return averageGrade; }
    public void setAverageGrade(double averageGrade) {
        this.averageGrade = averageGrade;
    }
}
```

Недостатки: по-прежнему возможно присвоение недопустимых значений (отрицательный возраст, средний балл вне диапазона).

**Финальный вариант:** добавлены конструкторы и валидация:

```java
/**
 * Класс, моделирующий сущность «Студент».
 * Демонстрирует применение инкапсуляции и валидации состояния.
 */
public class Student {
    private String name;
    private int age;
    private String group;
    private double averageGrade;
    private static int studentCount = 0;

    /**
     * Конструктор по умолчанию.
     */
    public Student() {
        this("Не указано", 18, "Не указана", 0.0);
    }

    /**
     * Параметризованный конструктор.
     *
     * @param name          фамилия, имя и отчество студента
     * @param age           возраст студента
     * @param group         номер учебной группы
     * @param averageGrade  средний балл
     */
    public Student(String name, int age, String group, double averageGrade) {
        setName(name);
        setAge(age);
        setGroup(group);
        setAverageGrade(averageGrade);
        studentCount++;
    }

    // Методы-аксессоры
    public String getName() { return name; }
    public int getAge() { return age; }
    public String getGroup() { return group; }
    public double getAverageGrade() { return averageGrade; }
    public static int getStudentCount() { return studentCount; }

    // Методы-мутаторы с валидацией
    public void setName(String name) {
        if (name == null || name.trim().isEmpty()) {
            throw new IllegalArgumentException(
                "Фамилия, имя и отчество не могут быть пустыми");
        }
        this.name = name;
    }

    public void setAge(int age) {
        if (age < 16 || age > 100) {
            throw new IllegalArgumentException(
                "Возраст должен находиться в диапазоне от 16 до 100 лет");
        }
        this.age = age;
    }

    public void setGroup(String group) {
        if (group == null || group.trim().isEmpty()) {
            throw new IllegalArgumentException(
                "Номер группы не может быть пустым");
        }
        this.group = group;
    }

    public void setAverageGrade(double averageGrade) {
        if (averageGrade < 0.0 || averageGrade > 5.0) {
            throw new IllegalArgumentException(
                "Средний балл должен находиться в диапазоне от 0.0 до 5.0");
        }
        this.averageGrade = averageGrade;
    }

    /**
     * Формирует строковое представление информации о студенте.
     */
    public String getInfo() {
        return String.format("Студент: %s, возраст: %d, группа: %s, средний балл: %.2f",
                             name, age, group, averageGrade);
    }
}
```

### 3.2. Пример 2. Класс «Банковский счёт» с бизнес-логикой

```java
/**
 * Класс, моделирующий банковский счёт.
 * Демонстрирует применение инкапсуляции, валидации состояния
 * и реализацию бизнес-логики.
 */
public class BankAccount {
    private String accountNumber;
    private String ownerName;
    private double balance;
    private boolean isActive;
    private static int accountCount = 0;

    /**
     * Конструктор для создания нового счёта.
     *
     * @param accountNumber  номер счёта
     * @param ownerName      имя владельца
     * @param initialBalance начальный баланс
     */
    public BankAccount(String accountNumber, String ownerName, double initialBalance) {
        setAccountNumber(accountNumber);
        setOwnerName(ownerName);
        setBalance(initialBalance);
        this.isActive = true;
        accountCount++;
    }

    /**
     * Конструктор по умолчанию.
     */
    public BankAccount() {
        this("0000000000", "Не указано", 0.0);
    }

    // Методы-аксессоры
    public String getAccountNumber() { return accountNumber; }
    public String getOwnerName() { return ownerName; }
    public double getBalance() { return balance; }
    public boolean isActive() { return isActive; }
    public static int getAccountCount() { return accountCount; }

    // Методы-мутаторы с валидацией
    public void setAccountNumber(String accountNumber) {
        if (accountNumber == null || accountNumber.trim().isEmpty()) {
            throw new IllegalArgumentException("Номер счёта не может быть пустым");
        }
        this.accountNumber = accountNumber;
    }

    public void setOwnerName(String ownerName) {
        if (ownerName == null || ownerName.trim().isEmpty()) {
            throw new IllegalArgumentException("Имя владельца не может быть пустым");
        }
        this.ownerName = ownerName;
    }

    /**
     * Приватный метод-мутатор для balance.
     * Прямое изменение баланса извне запрещено —
     * операции выполняются только через deposit() и withdraw().
     */
    private void setBalance(double balance) {
        if (balance < 0) {
            throw new IllegalArgumentException(
                "Начальный баланс не может быть отрицательным");
        }
        this.balance = balance;
    }

    /**
     * Внесение средств на счёт.
     *
     * @param amount сумма для внесения
     */
    public void deposit(double amount) {
        checkAccountActive();
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Сумма внесения должна быть положительной");
        }
        balance += amount;
    }

    /**
     * Снятие средств со счёта.
     *
     * @param amount сумма для снятия
     */
    public void withdraw(double amount) {
        checkAccountActive();
        if (amount <= 0) {
            throw new IllegalArgumentException(
                "Сумма снятия должна быть положительной");
        }
        if (amount > balance) {
            throw new IllegalArgumentException(
                "Недостаточно средств на счёте. Текущий баланс: " + balance);
        }
        balance -= amount;
    }

    /**
     * Блокировка счёта.
     */
    public void block() {
        if (!isActive) {
            throw new IllegalStateException("Счёт уже заблокирован");
        }
        isActive = false;
    }

    /**
     * Разблокировка счёта.
     */
    public void unblock() {
        if (isActive) {
            throw new IllegalStateException("Счёт уже активен");
        }
        isActive = true;
    }

    /**
     * Проверка активности счёта.
     * Вспомогательный приватный метод.
     */
    private void checkAccountActive() {
        if (!isActive) {
            throw new IllegalStateException(
                "Операция невозможна: счёт " + accountNumber + " заблокирован");
        }
    }

    /**
     * Формирует строковое представление информации о счёте.
     */
    public String getInfo() {
        return String.format(
            "Счёт №%s | Владелец: %s | Баланс: %.2f руб. | Статус: %s",
            accountNumber, ownerName, balance,
            isActive ? "активен" : "заблокирован");
    }
}
```

/**
 * Демонстрационный класс, отображающий возможности класса BankAccount.
 */
public class BankAccountDemo {

        BankAccount account1 = new BankAccount("1234567890", "Иванов И.И.", 10000.0);

        System.out.println("=== Созданные счета ===");
        System.out.println(account1.getInfo());

        // Операции со счётом

### 3.3. Пример 3. Перегрузка конструкторов и ключевое слово `this`

```java
/**
 * Класс, моделирующий точку на плоскости.
 * Демонстрирует перегрузку конструкторов и применение ключевого слова this.
 */
public class Point {
    private double x;
    private double y;

    /**
     * Конструктор по умолчанию.
     * Создаёт точку в начале координат.
     */
    public Point() {
        this(0.0, 0.0);   // вызов конструктора с двумя параметрами
    }

    /**
     * Конструктор с одним параметром.
     * Создаёт точку на оси X.
     *
     * @param x координата по оси X
     */
    public Point(double x) {
        this(x, 0.0);     // вызов конструктора с двумя параметрами
    }

    /**
     * Конструктор с двумя параметрами.
     *
     * @param x координата по оси X
     * @param y координата по оси Y
     */
    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    // Методы-аксессоры
    public double getX() { return x; }
    public double getY() { return y; }

    // Методы-мутаторы
    public void setX(double x) { this.x = x; }
    public void setY(double y) { this.y = y; }

    /**
     * Вычисляет расстояние от текущей точки до другой точки.
     *
     * @param other другая точка
     * @return расстояние между точками
     */
    public double distanceTo(Point other) {
        double dx = this.x - other.x;   // this.x — поле текущего объекта
        double dy = this.y - other.y;
        return Math.sqrt(dx * dx + dy * dy);
    }

    /**
     * Вычисляет расстояние от текущей точки до начала координат.
     *
     * @return расстояние до начала координат
     */
    public double distanceToOrigin() {
        return distanceTo(new Point());   // создание временного объекта
    }

    /**
     * Смещает точку на заданные величины по осям.
     *
     * @param dx смещение по оси X
     * @param dy смещение по оси Y
     * @return текущая точка (для цепочки вызовов)
     */
    public Point translate(double dx, double dy) {
        this.x += dx;
        this.y += dy;
        return this;   // возврат текущего объекта
    }

    /**
     * Формирует строковое представление точки.
     */
    @Override
    public String toString() {
        return String.format("(%.2f; %.2f)", x, y);
    }
}
```

## 6. Методические указания к самостоятельной работе

1. **Проектирование класса.** Перед написанием кода определите:
   - перечень полей и их типы данных;
   - инварианты класса — условия, которые должны выполняться на протяжении всего жизненного цикла объекта;
   - перечень допустимых значений для каждого поля;
   - методы, которые будут изменять состояние объекта, и методы, предоставляющие доступ к состоянию.

2. **Реализация конструкторов.** Параметризованный конструктор должен вызывать методы-мутаторы для инициализации полей, чтобы обеспечить выполнение валидации. При наличии нескольких конструкторов применяйте ключевое слово `this(...)` для устранения дублирования кода.

3. **Валидация данных.** В методах-мутаторах проверяйте все ограничения, накладываемые на значения полей. При нарушении ограничений выбрасывайте исключение `IllegalArgumentException` с информативным сообщением, содержащим описание проблемы и фактическое значение.

4. **Сокрытие реализации.** Если изменение поля должно выполняться только через бизнес-методы (например, изменение баланса счёта только через `deposit()` и `withdraw()`), не предоставляйте публичный сеттер для этого поля.

5. **Статические члены.** Статическое поле-счётчик должно увеличиваться в конструкторе. Статический метод, возвращающий значение счётчика, должен объявляться с модификатором `public static`.

6. **Бизнес-логика.** Методы, реализующие предметную логику, должны быть объявлены как нестатические (поскольку оперируют состоянием конкретного объекта). Вспомогательные методы, не обращающиеся к полям объекта, могут быть объявлены как `private`.

7. **Обработка исключений.** В демонстрационном классе продемонстрируйте обработку исключений, выбрасываемых методами класса, посредством конструкции `try-catch`. Сообщение об ошибке должно выводиться на консоль.

8. **Тестирование.** Перед сдачей работы убедитесь, что:
   - программа корректно компилируется без предупреждений;
   - все конструкторы и методы функционируют корректно;
   - валидация работает для всех полей;
   - обработка исключений выполняется корректно.

9. **Оформление отчёта.** В отчёт включите листинги всех файлов проекта, протокол работы программы, ответы на контрольные вопросы и выводы.
